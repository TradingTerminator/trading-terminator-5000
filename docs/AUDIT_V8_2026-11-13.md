## Security evidence

- RLS enabled on all 23 public tables at inspection.
- Inspected public/storage policies contain ownership checks. This is configuration evidence, not a cross-account penetration test.
- Chart bucket private, 10 MiB maximum, PNG/JPEG/WebP only. The app uploads new objects with upsert=false; no UPDATE policy required for that path.
- Advisors report two authenticated SECURITY DEFINER RPC warnings. Inspected functions include ownership/authentication checks and an empty search_path; the warning alone does not prove cross-owner access.
- Leaked-password protection is disabled per live advisor.
- stop_adjustments has an ALL owner policy. Its only non-internal trigger is AFTER INSERT; the closed-trade guard exists in record_stop_adjustment, not as a table-level UPDATE/DELETE guard. Thus the application/RPC restriction does not make the stored history immutable through direct permitted table operations. This is an integrity gap; no production mutation was attempted to demonstrate it.
- Shared auth/database remediation would affect V7 as well. Keep those changes separate and obtain the user's required V7-impact permission.
