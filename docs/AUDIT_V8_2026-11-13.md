## Function findings and prepared fixes

1. Original/Petrol and Light have no distinct palette; navigation and Start hero are hardcoded green. Provide complete six-scheme palettes, including navigation, hero and CTA tokens.
2. Compact, square-corner and larger-text controls omit some new V8 workspace elements. Extend them to the V8 cards and relevant controls.
3. The local diagnostic accepts only three of the six supported themes. Match the offered choices.
4. The final entry summary is calculated only when entering the step. Recalculate on allocation input/change and display an explicit message for invalid quantities instead of a stale total.
5. OTP input already has autocomplete=one-time-code, numeric input mode and explicit verification. The app merely displays a suggested subject; that does not configure Supabase email delivery. Actual email subject and iPhone extraction cannot be verified with current access.

## Logic checks

- Preserve the sequence: session readiness, explicit pre-entry emotions, setup/idea, account/risk, management/exit, situation/execution/learning review.
- Re-entry must select an existing idea; idea-only mode must not create a trade.
- Initial risk remains the basis for R. Financial outcome must remain separate from execution quality.
- The prepared risk-summary fix is display-only; transaction validation and stored initial risk remain unchanged.
- No automatic assumption that a checkbox confirms an observed trading signal, no fabricated setup criteria or trading recommendations.

## Security evidence

- RLS enabled on all 23 public tables at inspection.
- Inspected public/storage policies contain ownership checks. This is configuration evidence, not a cross-account penetration test.
- Chart bucket private, 10 MiB maximum, PNG/JPEG/WebP only. The app uploads new objects with upsert=false; no UPDATE policy required for that path.
- Advisors report two authenticated SECURITY DEFINER RPC warnings. Inspected functions include ownership/authentication checks and an empty search_path; the warning alone does not prove cross-owner access.
- Leaked-password protection is disabled per live advisor.
- stop_adjustments has an ALL owner policy. Its only non-internal trigger is AFTER INSERT; the closed-trade guard exists in record_stop_adjustment, not as a table-level UPDATE/DELETE guard. Thus the application/RPC restriction does not make the stored history immutable through direct permitted table operations. This is an integrity gap; no production mutation was attempted to demonstrate it.
- Shared auth/database remediation would affect V7 as well. Keep those changes separate and obtain the user's required V7-impact permission.
